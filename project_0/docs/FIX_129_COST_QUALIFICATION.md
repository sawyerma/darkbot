## Model and evidence boundary

`FailedCostMatrix` already has the six required *failure* cells (RPC, Jito single,
Jito bundle × not-landed/reverted). Keep its dimensions. Success costs belong to
`CandidateInput` and actual reconciliation; adding success cells to a failure
reserve would mix different meanings.

All matrix values are USD-micro. Wire/RPC evidence remains in lamports. Conversion
uses the existing exact-slot/time SOL bank price and rounds costs upwards. A missing
conversion stays UNKNOWN. Quote provenance includes message hash and RPC context slot.

Its successful landing proves payment; its execution revert pays no transfer but
still pays its network fee. An RPC/competitor transaction is never assigned a Jito
tip merely because a tip amount is configured elsewhere.

## Candidate economics

The RPC candidate now builds the final message before requesting its fee. The
candidate's success fee is the **total base + priority** fee; priority is not added
again. The existing conservative failure reserve prices **one additional failed
attempt**, at the same message fee. This reserve is a strategy budget, not a claim
that one transaction pays its fee twice or a probability-weighted expected value.

No global fee sample is reused across messages/signature counts/CU settings. RPC
scenario cells qualify only for an exact measured RPC message with no prerequisites
and no tip. Jito cells are not populated by RPC fee samples. Missing message fee,
conversion, realization or incremental rent keeps economics UNKNOWN.

Jupiter quote output already includes its route fees/impact; no invented second
impact deduction. Inventory realization stays UNKNOWN without its own evidence.
Prewarmed ATA rent is sunk, not charged per trade. A new LiquidationRecord's rent
is currently UNKNOWN, rather than silently zero or a universal rent constant.

`candidate_costs` preserves all compiled-candidate fee quotes and economic results,
including rejected negative candidates. No UNKNOWN result becomes an economic win.
