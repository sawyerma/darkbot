# DarkBot Control Gateway — F3

F3 transport layer for the browser. Protocol contract: `frontend/docs/GATEWAY_WIRE_PROTOCOL_V1_3.md`.

## Implemented
- Loopback-only default bind; host/origin restrictions; HttpOnly SameSite=Strict cookie session.
- `/api/v1/session` bootstrap, `/ws/v1/gateway` Protobuf websocket, `/healthz`, optional SPA static-serving.
- Hello/Welcome, bounded subscriptions and connections, latest-value state via Tokio watch, ordered generation/sequence, heartbeat/Pong and watermark.
- Overview source statuses; unavailable engine projections are not synthesized.
- Source-feed interface only. P0/BSC feeds and authenticated IPC are **not** connected.

## Boundaries
EVENT catch-up, command authorization/CSRF and production engine adapters are future phases. Trading and LIVE are not authorized. Gateway-owned overview data cannot be written through external EngineFeed.

## Verify
```bash
cd gateway
cargo fmt --all -- --check
cargo test --all-features
cargo clippy --all-features --all-targets -- -D warnings
cargo build --release
```
The above are commands, **not a claim of passing tests**. CI results must be checked.

Run local:
```bash
cd gateway
DARKBOT_GATEWAY_ALLOWED_ORIGINS=http://127.0.0.1:8080,http://localhost:8080 cargo run
```
Frontend Vite serves on loopback 8080; gateway proxies are dedicated to `/ws/v1/gateway`, `/api/v1/session`, and `/healthz`. Other existing frontend proxies are retained.

Production static SPA:
```bash
cd frontend && npm run build
cd ../gateway && DARKBOT_GATEWAY_STATIC_DIR=../frontend/dist cargo run --release
```

## Code generation
Rust `prost` types are generated by `gateway/build.rs` from `protocol/schemas`. Frontend TypeScript bindings must be generated with Buf. `SCHEMA_ID=TO_PIN` remains a qualification blocker until both ends pin the same schema identity.

## Safety
All work goes directly to `main`. No development branches. Preserve `project_0/` and `bsc/` unchanged.
